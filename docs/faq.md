# 常见问题

报错类的问题先跑 `filmwright check --project <项目目录> --static-only`，十道自检里有七道不启浏览器、秒级就能定位引用错。这里收「为什么」类问题；明确不做的功能见 [LIMITATIONS](../LIMITATIONS.md)。

## 报错：时间轴未装载就查询了 S01

镜头文件在**模块顶层**就调了 `cutBefore('S01')` 这类查询，而查询要求时间轴已装载。引擎因此要求把镜头作为**加载函数**传给 `boot()`（`loadShots`），由它保证求值顺序——直接 import 已求值的镜头模块再 boot 就会撞上这个错。渲染页已经按正确顺序装配，通常只有自己写页面时才会遇到。

## 报错：第 X–Y 帧没有镜头接管

只声明了 `start` 但两个镜头之间留了空隙（或第一个镜头的 `start` 不是 1）。镜头区间由引擎串接：下一个镜头的 `start − 1` 就是上一个镜头的末帧，引擎要求从第 1 帧起无缝覆盖到总帧数。同理，「镜头只覆盖到第 X 帧，时间轴共 Y 帧」说明最后一个镜头之后缺一段。

## 报错：不存在的句 id / 句 SXX 没有第 k 个字幕块

镜头里 `S('S05')` / `BLK('S02', 3)` 引用了时间轴里不存在的句或字幕块。先看 `script/timeline.md` 核对 id 与块数；多半是解说词改了（句数变了），镜头引用的 id 还留着旧的。

## 改了解说词，动画节拍会乱吗

不会，前提是镜头动画的起点用 `S()` / `BLK()` 查询而不是硬编码帧号。逐句缓存按内容寻址：改一句只重合成那一句，后面所有句子的帧号自动平移，跟着 `S()` / `BLK()` 写的镜头自动对齐。

## 页面/渲染完全没有画面，也不报错

最常见的是**模块相对路径写错**——页面会静默不 ready。跑静态自检的 `imports` 那道能直接列出断掉的路径。另外模块加载失败是完全静默的，可以用 `tools/boot-error.mjs` 取 `window.__bootError`。

## 字体没生效 / 首帧字体不对

`boot()` 会等配置里 `fontFiles` 声明的字体全部加载完才开画；字体**加载失败会回退不报错**。检查文件是否在 `public/fonts/` 下、`font-family` 名字是否与声明一致。图片素材则相反——失败是抛错，不是空白。

## 内容挤在画布左边（换分辨率后）

镜头坐标是设计坐标，输出分辨率变大时要 `applyDesignScale(ctx)`。引擎内建件（HUD / 字幕 / 章节卡 / 进度条）自动适配，镜头内容要自己套。推荐在镜头入口统一套（教程里的 `withDesign` 包装）。

## 画质自检报「静止过久」，但画面明明有轻微动作

「静止」的判据是**累积**的，采样口径下能读到的最小变化有底限——0.5% 那种呼吸幅度读出来是 0.2–0.4 的灰度差，等于没动。把动效幅度加大（示例里用的是 3.5%–5% 的呼吸），或用 `--static-frames` 等参数放宽阈值（见 [LIMITATIONS](../LIMITATIONS.md) 的校准说明）。

## 画质自检报了，但画面其实是好的

先怀疑检查器还是怀疑画面：用 `stills` 出那几帧看一眼，再决定是修片子还是调阈值。阈值是按 1280×720 的 32×18 网格校准的，换分辨率或换题材后默认值不一定合适。

## 渲染一帧要多久 / 怎么变快

**稳态**实测参考：1280×720 约 **20 ms/帧**（单实例，默认档；≈1.7× realtime）。
注意别拿"短渲染的 ms/帧"当稳态 —— 浏览器启动约 1.7s 是一次性的，
摊到几十帧上会把数字算得虚高（60 帧渲染看起来像 50ms/帧）。
本文件原来写"约 81 ms/帧"，那是**旧代码 + 旧测法**的数字，已过期。

变快的三条路，各自的实测结果：

| 手段 | 实测 |
|---|---|
| `--shards N` 分片并行（每片一个浏览器实例） | **2 片最好：2.23× realtime**；4 片反而更差、6 片明显更差 |
| `--gpu` 放开 GPU | 效果链与 3D 要用它才跑在真 GPU 上；代价是 2D 像素会变 |
| `--frame-format h264`（WebCodecs 页面内编码） | 端到端 **1.34×**（省掉"编 JPEG + ffmpeg 再编一遍"） |

**10× realtime 的目标在本机未达成** —— 瓶颈已从"取像素"转移到**软件编码器的吞吐**。
完整的实测与边界见 [LIMITATIONS](../LIMITATIONS.md) 第 6 节。

## 换了浏览器/机器，画面会不一样吗

钉死了 `--force-color-profile=srgb` 之后，实测系统 Edge 与 Chrome-for-Testing 渲同一帧**逐像素完全相同**（不加这个参数会有 85% 像素差 1–8 级）。`tools/verify-reuse.mjs` 就是验这件事的。

## 末拍稳定期是什么，为什么它不判失败

画质自检里的一条读数：最后一拍落位到镜头结束有多久。它只报告不判失败——像素 diff 分不清一次变化是「入场」还是「离场」，而这恰恰要求区分。三种读法都试过、都不对，与其加绕的启发式不如如实降级成读数（详见[质检](qc.md)）。

## 能出 SRT 字幕吗

字幕是烧进画面的，本库不提供导出；需要时从 `script/timeline.json` 的 `subs` 自己导出（见 [LIMITATIONS](../LIMITATIONS.md)）。

## 只在 Windows 上能用吗

管线是跨平台的（浏览器查找列表含 macOS / Linux 路径），但**目前只在 Windows 上实测过**，其他平台的状态见 [LIMITATIONS](../LIMITATIONS.md)。
